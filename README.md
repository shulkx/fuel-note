# 车账本（Car Ledger）

在 Scripting 里运行的用车账本：

- 记加油和费用，自动算油耗。
- 可以连接小熊油耗，与官方 App、网页版共用一份数据。
- 可以读取沃尔沃行程，填入里程、时间和油站。

设计与实施：

- 设计文档：`docs/specs/2026-10-18-car-ledger-design.md`
- 实施文档：`docs/plans/2026-10-18-car-ledger-v1.md`

## 入口

- `index.tsx`：主界面，分记录、统计、设置三个标签。
- `widget.tsx`：桌面小组件（小号、中号），点击直接打开「记加油」。

## 使用

### 只用本机

在「设置 › 车辆」添加车辆，然后在「记录」页点右上角的「+」。

- 单价、升数、机显金额任填两项，自动算出第三项。
- 实付默认等于机显金额。
- 油耗按跳枪法计算：两次加满之间为一段，结果显示在后一次加油上。

### 连接小熊油耗

1. 在 Surge 中启用「小熊油耗 · 凭据抓取」，打开小熊油耗 App 的会员页；然后在 BoxJS 中复制 `xxyh_auth`。
2. 打开「设置 › 小熊油耗」，粘贴后点「连接」。小熊里的每辆车都会出现在车账本里。
3. 之后在车账本里新增、修改、删除记录，保存后会自动上传为新的云备份版本。打开 App 时会拉取官方 App、网页版的修改。

注意：

- 上传前总是先下载云端最新版本，只改动这次修改的记录；车账本不认识的字段原样保留。
- 每次下载和上传的版本都会保存在本机，留最近 5 个，供出问题时找回。
- 官方 App 登录时会上传它本地的整份数据。如果它的数据是旧的，会覆盖车账本的修改，所以建议不再在官方 App 里登录。网页版在编辑前要先刷新。
- 保养记录只显示，不能编辑。

### 连接沃尔沃

1. 在 Surge 中启用「沃尔沃 · 凭据抓取」，打开沃尔沃 App；然后在 BoxJS 中复制 `volvo_auth`。
2. 打开「设置 › 车辆数据 › 沃尔沃（中国）」，粘贴后点「验证并读取车辆」，再把沃尔沃的车关联到车账本的车辆。
3. 记加油时点「从行程选择」：
   - 列出最近 7 天的停车，加油停车排在前面；
   - 选中后填入熄火时的里程、时间，以及油站。

加油停车的判断规则：

- 离「我的油站」80 m 以内，且停留不超过 45 分钟；或者
- 停留不超过 30 分钟，且附近 60 m 内有加油站。

附近加油站的搜索方式在「设置 › 油站搜索」中选择：有高德 Web 服务 key 时用高德，否则用小熊油耗的附近油站。

## 凭据与数据

- 凭据只保存在本机钥匙串。
- 数据文件在 Scripting 的 App Group 目录 `CarLedger/` 下：
  - `ledger.json`：本机车辆和记录；
  - `xxyh.json`：小熊同步状态；
  - `xxyh_snapshots/`：最近 5 个小熊版本。
- 「设置 › 数据 › 导出 JSON」把全部车辆的记录导出到 Scripting 的文稿目录。

## 开发

在 `E:\scripting` 运行开发服务器，手机上的 Scripting 连接后选择本脚本：

```sh
npx scripting-cli start
```

检查与测试（在本目录）：

```sh
npm install
npm run check                                    # tsc，用 ../../dts 的 Scripting 类型
npm test                                         # Node 单元测试（合成数据）
XXYH_ROOT=E:/GitHub/xxyh npm test                # 另外与真实数据核对（只读）
LIVE=1 XXYH_ROOT=E:/GitHub/xxyh npm test         # 另外在线只读：小熊下载最新版本、沃尔沃读取行程
```

- 真实数据只从 `XXYH_ROOT` 读取，不提交到本仓库。
- 在线测试会拒绝所有写入请求。

### 接入新的车辆数据提供方

1. 新建 `providers/<brand>.ts`，实现 `VehicleDataProvider`（`providers/types.ts`）。坐标转成 WGS-84，里程转成公里。
2. 在 `providers/registry.ts` 中登记。

设置页和「从行程选择」都通过接口使用提供方，接入新品牌不用改界面。
