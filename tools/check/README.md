# FuelNote Check：手机上的自动检查

开发用，不随油记发布。电脑通过手机上开的端口触发检查，结果和截图传回电脑，代替一部分手机验收。

## 它做什么

- **识别**（`recognize`）：从电脑上的采样服务取保单文件（`XXYH_ROOT/materials/insurance/`），在手机上用油记的 `readPolicyFiles`、`scanPolicyFile` 读出保单和交强险标志，电脑和 `XXYH_ROOT/out/insurance/expected.json` 逐项比较。读不出文字的 PDF 用这一页上的 WebView 截图识别。PDFKit 取出的原文一起传回，`out/insurance/pdfkit.jsonl` 里还没有的由电脑补上，所以新加的保单不用再跑 Probe。
- **记账**（`ledger`）：电脑按本机数据（`expected.json`、最新的小熊云备份）生成计划，手机在检查用的账本上用本机测试车做一遍并逐步核对：导入各年保险、补到小熊里已有的费用（保留原金额或改成合计）、改优惠、改付款日期、升级时挂交强险标志、续保提醒、删除、备份后恢复。
- **截图**（`shots`）：用记账之后的账本渲染真实页面（保单详情、编辑表单、保险页的续保提醒），浅色、深色各一张，页面撑高后一张图看到整页。
- **油耗与费用**（`split`，1.6）：电脑把最新的小熊云备份发给手机，手机在检查用的文件夹里建一辆关联小熊的车（`xxyh.json` 的 base 就是这份备份，从不同步、不上传），照记账的做法导入各年保单；再核对油耗的统计只算加油、费用和保养合成一行只算一次、费用页和费用统计不含车险（合计、笔数、各类别、每年）、保险页的年数和只有金额的笔数、`widget.json` 只算加油，期望值由电脑用同一套纯函数从同一份备份算出。最后截图：油耗的记录和统计、费用的记录和统计、记费用、保险页、2021 年的保单详情（1.6.0-beta.4）。

- **权益**（`benefits`，1.7，要在 `split` 之后）：电脑把 `XXYH_ROOT/out/benefits/benefits.json`（用户的车险赠送原文和条目、套餐、门店）发给手机，在 `split` 建的那辆关联小熊的车上加门店；用 Scripting 助手识别车险赠送的原文（发送前去掉个人信息）和套餐截图，和手动整理的条目数比（套餐的每一项都应是次数，名称、售价、有效期都要认出）；添加车险赠送、套餐（同时记一笔维修保养费用），记一笔用了权益的维修保养费用、记一次使用，改一批的有效期，删除用过的卡（费用不动）；核对剩余、分组和顺序、续保提醒的赠送、保单详情的「赠送」一行、费用的金额和备注、权益抵扣、小熊操作的上传前检查。截图：权益页、一批、权益详情、已用完和已过期、添加权益（识别后）、编辑权益、编辑一批、记一次使用、使用权益、用了权益的费用、选择门店、2026 年的保单详情。

## 不碰真实数据

- 启动时 `setDataRoot("FuelNoteCheck")`：账本、保单原件、小组件文件都在 App Group 的 `FuelNoteCheck/` 下；清空前会核对文件夹名。
- 不读写钥匙串、不同步小熊、不读车况；只向电脑上的采样服务取保单文件。
- 例外：`benefits` 把车险赠送的原文（去掉手机号、证件号、车牌、车架号后）和套餐截图（`XXYH_ROOT/out/benefits/package.png`，有时才发）发给 Scripting 助手识别，和油记里添加权益时一样。
- 真实数据只在电脑的 `XXYH_ROOT` 里：计划由电脑生成后发给手机，结果和截图存到 `XXYH_ROOT/out/check/`，不进仓库。

## 用法

1. 电脑上开着开发服务器（`E:\scripting` 里 `npx scripting-cli start`）和采样服务（`npm run ocr-bridge`）。
2. `npm run check:install`：把这里的检查程序连同油记的代码复制到 `../FuelNote Check`。只写有变化的文件，先写临时文件再改名（直接覆盖时手机可能按旧内容重新运行）。
3. 第一次：手机上新建一个空脚本「FuelNote Check」，在开发服务器页面里选它，运行。之后改了代码再装一次，手机会自己用新代码重新运行（约 2 秒）。
4. 手机上这一页留在屏幕上、屏幕不锁。它向采样服务报到，地址写到 `XXYH_ROOT/out/check/phone.json`。
5. 电脑上：`XXYH_ROOT=E:/GitHub/xxyh npm run device-check`（或只跑一部分：`… device-check -- recognize ledger shots split benefits` 里选；`shots` 要在 `ledger` 之后，`split` 会清空检查用的账本，`benefits` 要在 `split` 之后）。

改了 `runner.tsx` 后把 `STAMP` 加一，`/ping` 返回的 STAMP 就能确认手机跑的是新代码。

## 不能自动检查的

真的点按和手势（左滑删除、轻点徽章全屏显示、拨号、选文件、「识别扫描件」里的取消、推入和返回、记费用分段的切换、「+」的轻点）、真实的小熊同步、标签栏、桌面上的小组件，以及用户真实数据第一次升级时的结果，仍要在手机上看。
