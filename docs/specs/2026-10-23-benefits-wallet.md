界面草稿：画布「第九轮 · 权益改成卡包式」。按公开仓库不放真实数据的约定，这里只写结构和规则，金额、门店名在画布和本机数据里。

## 1. 要解决的事

用户一年用到权益的次数是个位数：每年一批车险赠送（约 5 项），偶尔买一个保养套餐（十几项，几年有效），每年两三次保养。要做的只有四件事：

1. **别浪费**：知道手里有什么、什么时候到期，到期前提醒。
2. **用的时候快**：到店或记费用时看到能用的，用完记下。
3. **回顾**：续保时看今年送了什么、用了多少。
4. **账对**：费用记实付，权益不另算一份钱。

## 2. 概念

| 概念 | 含义 |
|---|---|
| 权益 | 一张卡：一项赠送、一张抵用券、套餐里的一项服务 |
| 类型 | 储值（一笔钱，分几次用，按金额抵扣）、次数（一项服务或一张券，用掉几次，不抵钱；抵用券也按次数记，单位「张」）。不记价值（用户 2026-10-23：套餐上标的价值只是宣传，记下来会被误导） |
| 剩余 | 总量减去使用记录的用量 |
| 有效期 | 卡上的到期日；不填为不限 |
| 门店 | 卡上的一段文字，只作提示，不用来筛选 |
| 来自 | 卡上的标签：某一年的车险，或一段文字（套餐名）；同一来自的卡放在一起显示 |
| 使用记录 | 一次使用：日期、用量、抵扣，可以注明记在哪笔费用上 |
| 用于记费用 · 记一次使用 | 两种使用：有费用的在记费用里勾，不花钱的单独记 |
| 已用完和已过期 | 用完或过期的卡自动收进这一页 |
| 抵扣 · 实付 | 记费用时，储值从金额里减去的钱；费用存实付 |

不再有的概念：来源（组）、条目、追踪、保单自带的服务、适用类别、每次最多抵扣、组名规则、并组。

## 3. 数据

```ts
type Perk = {                 // 一张卡
  id: string; vehicle_id: string
  name: string
  kind: "balance" | "count"   // 储值、次数
  total: number; unit: string // 储值是元；次数是次、张、面、瓶
  end_ts: number | null       // 有效期至；null = 不限
  store: string               // 门店名，可空
  source: string              // 来自：「2026 车险」「回馈季保养套餐」
  insurance_id: string | null // 来自某一年的车险时填；只用来在保单详情和续保提醒里找到它
  origin: "insurance" | "package" | "other"  // 添加时选的种类：图标颜色；车险赠送的来自名称不能改
  raw: string                 // 添加时粘贴的原文，同一批的卡各存一份；识别截图时为空
  note: string
  created_ts: number
}

type PerkUse = {              // 一次使用
  id: string; perk_id: string; ts: number
  used: number                // 储值是元，次数是次（或张、面、瓶）
  deduct: number              // 从费用金额里减去的钱：储值 = used，次数 = 0
  expense_id: string | null   // 2.0 起：记在哪笔费用上（费用的 id）；null = 记一次使用。1.x 是 expense_ts（按时间），电脑转换时换成 id
  note: string
}
// LedgerFile.perks、perk_uses、stores（2.0 起都是必有的列表）；费用的门店是 ExpenseRecord.store_id（2.0 起）
```

## 4. 规则

- **状态**：剩余 > 0 且没过期为可用；剩余 = 0 为已用完；过了有效期还有剩余为过期未用。
- **分组**：权益页按「来自」分组（有 `insurance_id` 的按保险年度，其余按 `source` 文字），组按组里最早的到期日排。分组只是显示，不存。
- **添加一批**：来自、有效期、门店、原文填一次，加几项，保存后是几张独立的卡。
  - 车险赠送：选哪一年的车险，来自写「2026 车险」，有效期默认取这一年的保险到期日（保存时写进卡里，以后不联动）。
  - 保养套餐：填名称、价格、购买日期、有效期。开关「同时记一笔费用」默认打开，保存时记一笔维修保养费用（金额是价格，时间是购买日期，备注是名称和门店）；只记这一次，之后费用和卡互不影响，也不找回、不同步。
  - 其他：名称、有效期。
  - 名称和同一来自里已有的卡相同时，先提示「可能重复」。
- **一批的操作**（轻点组名推入）：添加一项；右上角「编辑」一次改这一批的来自名称、有效期、门店、原文，改完写进每一张卡（车险赠送的来自名称跟着保险年度，不能改）；最下面删除整批。
- **使用**：
  - 记费用里的「使用权益」列出所有可用的卡，不按门店、类别筛选。储值填抵扣金额，默认取剩余和还没抵扣的金额中较小的；次数（含抵用券）勾上就是 1 次，可以用步进器加，不抵钱。几项一起用时，依次从金额里扣，抵扣合计不超过金额。实付 = 金额 − 抵扣合计。
  - 费用的金额写实付。2.0 起门店存在费用的 `store_id`，用了什么看使用记录，备注只留用户写的；「维修保养券抵扣 ¥… · 基础保养 1 次 · <门店>」这一行只在导出到小熊时写进备注的最后一行（`usageLine`）。1.x 把这一行存在备注里，打开时再拆开（`splitRemark`，2.0 删掉）。
  - 记一次使用：半屏，日期 · 用量 · 备注，不另记费用；记一次使用的记录可以轻点修改、左滑删除。
  - 删除费用时，这笔的使用记录一起删除，剩余恢复（沿用 1.7.0-beta.1）。对应的费用不在了的使用记录（1.x 在小熊里改了费用日期时会这样）照样显示、照样算用量，第二行写「没有对应的费用」，可以左滑删除。
- **编辑一张卡**：都能改。用过的不能改类型，总量不能少于已用。改名不影响已经写进费用备注的文字。
- **删除**：一张卡或一批，都不受费用限制。确认里写明一起删除的使用记录条数；记过的费用不变（实付和备注都不动），费用统计里不再算这些抵扣。
- **提醒**：只在页面里。到期前 30 天起组头标橙，写到期日和未用完的项数；和车险同一天到期、来自这一年车险的卡并进续保提醒（「赠送 N 项未使用」）。
- **统计**：费用统计的「权益抵扣」= 范围内、记在现存费用上的使用记录的抵扣合计。费用合计照旧是实付。
- **保险**：保单详情「服务」一行照 1.5 只读；下面一行「赠送」列出来自这一年车险的卡和使用情况，轻点推入这一批。删除一年的保险时，卡照留（来自和有效期都存在卡上）。
- 权益、使用记录、门店名只存在本机，进备份。

## 5. 添加：入口和识别

### 5.1 入口

一张「添加权益」表单，两个入口。入口只管预先填好内容，不管数据（用户 2026-10-23 决定保留保单详情的入口）。

| 入口 | 预先填好 |
|---|---|
| 权益页「+」 | 车险赠送 · 正在保障的那一年；可以切到保养套餐、其他 |
| 保单详情「赠送」一行（这一年还没有赠送时写「添加」） | 车险赠送 · 这一年，有效期取这一年的保险到期日 |

三条边界，以后加需求先对照：

1. **入口只管预填，不管数据**：任何入口都打开同一张表单，保存后只生成卡，不和来源保持关联。
2. **记保险、记费用这两张表单里不放权益**：保单详情只有「赠送」一行引用，用来列出和添加。
3. **卡上的东西只在卡上改**：不跟随保单期间、费用金额，也不反过来改它们；删卡不动钱，删保险不动卡。

只在已经有引用行的地方放捷径：保单详情本来就有「赠送」一行，所以有添加入口；费用没有这样的一行，买套餐在权益页添加，顺手记那笔费用。

### 5.2 识别

用户 2026-10-23：不想手动添加，第一版就做。

- 表单最上面一组「识别」，分段 文字 · 截图：
  - 文字：粘贴销售发来的消息（车险赠送一般是这种）。
  - 截图：4S 店小程序的权益页、纸质清单的照片，可以选几张（套餐一般是这种）。
- 用「设置 › 识别方式」选的大模型：Scripting 助手（`Assistant.requestStructuredData`，油记识别加油截图已经在用）或 Azure OpenAI。本机识别整理不了这种内容，选了本机时提示换一种。
- 按 JSON schema 返回：
  - 每一项：名称、类型（储值 / 次数）、数量、单位、说明。名称去掉数量词；储值的金额不写进名称，次数名称里的金额照原文保留（「基础保养400元抵用券」）。规则：只写金额、没写张数次数的是储值；写着「一张」「一次」「一个面」的是次数，带金额的抵用券、抵扣券也是次数；「价值」「原价」不记，也不据此认成储值；
  - 这一批：套餐名（原文没有明确名称时按标题起一个简短的）、售价（实际要付的钱，不是价值）、有效期的说法、门店的说法；名称、售价、有效期填进表单里还空着的字段。
- 填进表单，逐项列出、默认勾选，可以改、可以去掉：
  - 「有效期一年」「本店」这类说法换算成日期和门店后标橙，要用户确认；原文没写门店时按最近一笔维修保养的门店填，同样标橙；车险赠送的有效期照旧取保险到期日。
  - 保单自带的服务（代驾、道路救援等，按险种名称表认）默认不勾，注明「保单自带的服务，在保单详情里」。
  - 和这一来自已有的卡同名的默认不勾，注明「已有」。
- 原文存进这一批每张卡的「原文」：文字原样存；识别截图时不存（截图不进账本，模型返回的是整理好的几项，不是原文）。
- 没确认不保存。识别失败、没有配置识别方式时，照常手动添加。
- 隐私：文字发出前去掉手机号、证件号、车牌、车架号、发动机号；截图原样发送，界面上写明。
- 用户的真实原文（2026 车险赠送）由 FuelNote Check 用 Scripting 助手识别，和手动整理的条目数比对；套餐截图在手机上验收。
- 识别方式在「设置 › 识别」一组的「识别方式」（原「记加油」里的「截图识别」）。
- 代码：`readers/perk_llm.ts`（提示词、两种 schema、把结果整理成表单条目、认出保单自带的服务）；`platform/assistant.ts`、`readers/azure.ts` 加结构化请求（没有图片时只发文字）；`common/redact.ts`（发出前去掉个人信息）；`common/model.ts` 的 `recognizePerks`。

## 7. 不做

- 保单自带的服务的追踪：道路救援、代驾等是保单条款，在保单详情里只读。
- 适用类别、每次最多抵扣、按门店筛选：用户的权益都按不限算，一年用几次，列出全部就够。
- 高德搜索门店：门店只是提示文字，从费用备注认出的店名和手动输入够用。
- 套餐和那笔费用的关联、价格同步、「重新记一笔」。
- 在记保险、记费用表单里添加权益（5.1 节的边界）。
- 从保单 PDF 里认赠送：保单上没有赠送。
- 识别后直接保存：识别会出错，必须确认。
- 系统通知（用户 2026-10-22：先不加）。
